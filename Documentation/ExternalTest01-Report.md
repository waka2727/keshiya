# 消し屋 External Test 01 実装・配布報告

## 配布物

`Builds/Keshiya-ExternalTest01.zip` を展開して `Keshiya.exe` を起動します。Unity Editorは不要です。
通常のWindows x64 Monoビルドで、Development Buildではありません。画面には開発中の試遊版であることを明示しています。
配布対象は8依頼。起動中のみ進行を保持します。本格セーブやコンテンツ・性能・報酬バランスの変更は行っていません。

## 変更したファイルと役割

全一覧は `ExternalTest01-ChangedFiles.txt`。新規C#の.metaもUnityにより生成されています。

- `ExternalTestPolicy`：試遊バージョン名、通常プレイの開発機能無効化。Editorまたは明示的な旧回帰テスト起動のみ開発機能を許可。
- `ExternalTestSession`：起動案内、F1ヘルプ、チュートリアル・一度きりの案内、F2 FPS、全進行初期化、ログへのイベント接続。
- `TutorialHints`：7段階の操作ヒント。任意の先送り・スキップ・再表示が可能。
- `SessionJournal` / `TestLogEntry`：許可したゲームデータだけをJSON Linesでローカル保存。
- `RuntimeExternal01Checks`：通常版と同じDebugMode=falseの状態で試遊フローを検証。
- `External01Build`：既存Editorチェック・外部アートチェック・非DevelopmentのWindowsビルド。
- `PrototypeGame`：依頼開始／終了／やり直し、道具購入／切替、スキル取得をログへ接続。
- `PrecisionViewport` / `PreviewViewport`：ホイールのズーム修飾をCtrlへ変更。座標変換・倍率・パン計算は維持。`RuntimeUXChecks`も最終操作に合わせて確認。
- `EraserController` / `PrototypeHUD` / `PrecisionAssist`：ヘルプ中の入力を止め、操作ヒントへのクリックが紙へ貫通しないようにする。
- `ShopHUD` / `SkillHUD` / `WorkFlowHUD`：通常起動でデバッグ操作と旧依頼切替を非表示・無効化。
- `CrumbTradeHUD`：通常プレイでは長尺カスの作り方を直接説明せず、回収・売却だけを案内。見本中の玉ボタンの入力遮断も補強。
- `ProjectSettings.asset`：試遊版の製品名／バージョン、通常Player.logを無効化。既存の1280×800ウインドウ設定を維持。
- `Tools/ExternalTest/package.py`：配布ファイルの許可リストでZIP生成、CRC・同梱内容・開発パス混入を検証。
- `ExternalTest01-README.txt` / `ExternalTest01-Feedback.txt`：配布文面の原本。ビルド直下のREADME.txt／Feedback.txtにも配置。

## 起動と操作ヒント

起動時に短い開発中の表示、自由試遊の案内、進行は起動中だけである旨を表示。
「最初の依頼を読む」はTEST_001の詳細へ、「自由に依頼を選ぶ」は一覧へ移動します。8依頼はすべて最初から選択可能です。

TEST_001の作業中に、次の7項目を1つずつ表示します。

1. マウス移動と左ボタンで擦る。
2. 激しい擦り方による紙ダメージ、制限時間なし。
3. Q/Eの面・辺・角。
4. R回転と接触ガイド。
5. Wheel上下移動、Ctrl＋Wheelズーム、中ドラッグ、Home。
6. Space吹き払い、C回収、G玉、V買取。売却は任意。
7. 95%で依頼完了、作業中のやり直し。

自動送りは各18秒、最初だけ消去を始めるまで最大30秒。通常は約2～3分です。テストでは7段階を217秒以内で完了できることを検証しています。依頼を終える実時間を保証するものではありません。
ヒントは操作を奪わず、ボタンで先へ進めたり閉じたりできます。F1から再表示／スキップできます。
TEST_002には一般的な細部操作、最初の精密作業には完成見本、最初の報酬にはショップ、初SPにはスキル画面を一度だけ案内します。
特定依頼の正解の道具、長尺カスの作り方、購入するべき品は教えません。依頼詳細の既存「候補」道具名も通常試遊では非表示にし、依頼文・消すもの・残すものは維持しました。

## 初期状態とリセット

毎回起動時：所持金0円、普通・やわらか・砂消し各1本、新品、スキルLv0、3系統EXP/SP=0、依頼完了数0、購入履歴・使用記録なし、カス在庫／玉なし。
接触ガイドON、持ち込み制限OFF、FPS表示OFF。スターター品は既存仕様どおり所持品として識別されますが、購入／使用実績は未登録です。
開発者の進行やデバッグLvを読み込む保存処理はありません。

作業中「やり直す」は既存の確認付きトランザクションを維持。現在依頼の紙・消去・保護損傷、カス、道具残量／角／特殊状態、今回の取引・進行を開始時スナップショットへ戻します。
F1 →「テストデータ初期化」→確認は、シーンを再ロードして全進行を初期状態へ戻します。キャンセル可能。ログは削除しません。

## 操作・画面

作業と完成見本は、既存の共通操作を維持しています。
Wheel=上下、Ctrl＋Wheel=ズーム、Home=全体、中ドラッグ=パン。代替の＋／－ズームも利用可能。
World上の接触サイズや既存接触ガイド・判定の共通化は変更していません。最終指示に合わせ、左右どちらのCtrlにも対応。Shift＋Wheelはズームになりません（Shift＋Rの逆回転は維持）。
依頼詳細の大きな「依頼者からの手紙」と「作業情報」の分離も維持しています。

F1：ヘルプ／設定。F2：FPS表示。ガイドON/OFFもF1から変更できます。
F3/F4/F8/F9は通常起動ではデバッグ機能を発動しません。ショップの資金追加・全品解放・摩耗変更、スキル即時Lv変更は表示されません。
自動回帰チェック用の明示的なコマンドライン起動は開発用途として残しています。友人は引数なしでexeを起動します。

## ローカルログとプライバシー

保存先：`Application.persistentDataPath/ExternalTest01/Logs`。
Windowsでは `%USERPROFILE%/AppData/LocalLow/Keshiya Studio/消し屋 External Test/ExternalTest01/Logs`。
ファイル名はUTC時刻とランダム短縮値。各行を書き出すため異常終了時も直前までの記録が残りやすい構造です。

記録：起動、依頼選択・開始・完了・中断・やり直し、購入、道具切替、スキル取得、全進行初期化、終了、エラー種別。
依頼ID、道具定義ID、接触時間、消去量、紙／保護損傷、面辺角の距離割合、評価、所持金、EXP/SP、やり直し回数を保持。作業中は15秒間隔の状態記録も行います。
重大損傷はmajorDamageで記録。既存ゲームの評価を失敗扱いにする新しいルールは追加していません。
終了時に平均FPSと最長フレーム時間の逆数を記録。最低値にはロード等も含むため、安定したプレイ時の性能下限を示す数値ではありません。

Windowsユーザー名、実名、IP、端末ID、ローカルパス、生の例外メッセージ／スタックは書きません。ハードウェア名の取得は今回は省略しました。起動時の解像度のみ記録します。
文字列フィールドは英数字等のID用許可リストを通します。疑似個人パス・IPを含むエラーを発生させ、専用ログへ含まれないことを検証しました。
通常Player.logは無効化し、例外はエラー種別と最後の依頼情報に限って専用ログへ残します。このため詳細スタックによる原因特定はできません。調査時は操作状況の説明も必要です。
自動送信はありません。OSやUnityクラッシュハンドラが独自に作るクラッシュ資料まで、この独自ログの匿名化保証の対象にするものではありません。

## 配布文書と構成

README：起動、開発中表示、自由な30～60分試遊、基本操作、ヒント、やり直しと全初期化の違い、起動中のみの保存、不具合の伝え方とログについて。
Feedback：指定された10項目と任意の総評／不具合欄。回答や全依頼クリアを強制しません。

```
Keshiya-ExternalTest01/
  Keshiya.exe
  Keshiya_Data/
  UnityPlayer.dll
  UnityCrashHandler64.exe
  MonoBleedingEdge/
  D3D12/
  README.txt
  Feedback.txt
```

ソース、Unityプロジェクト、テスト結果、スクリーンショット、開発ログ、デバッグシンボルはZIPへ含めません。
再配布はビルド後に配布文書をコピーし、`python Tools/ExternalTest/package.py` で再生成できます。

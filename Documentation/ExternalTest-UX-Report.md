# External Test UX改善レポート

今回の対象は操作・案内・表示のみです。8依頼の文章・画像・マスク、紙／筆記具／消しゴムの性能、スキル倍率、報酬、消しカス経済は変更していません。

## 起動

`Builds/Windows-ExternalTest-UX/Keshiya.exe` を起動します。以前の `Windows-ExternalTest` は比較用に残しています。
配布時は `Keshiya-ExternalTest-UX.zip` 全体を展開し、実行ファイルだけでなく隣のDataフォルダー等も保持してください。

## 操作

| 操作 | 作業用紙・完成見本の挙動 |
|---|---|
| Shift + Wheel | カーソル付近を中心に拡大・縮小（1～4倍） |
| Wheel | 上下スクロール。ズーム倍率を変えない |
| 中ボタンドラッグ | 上下左右へパン |
| Home | 全体表示へ戻す |
| H / 完成見本 | 精密依頼の納品見本を開閉。Escでも閉じる |

作業画面左上に「やり直す」を追加。接触モードの下の「ガイド ON/OFF」で正式ガイドを切り替えられます。数字キー、面／辺／角、R回転、回収・売却等の既存操作は維持しています。

## 主要クラス・変更ファイル

全一覧は `ExternalTest-UX-ChangedFiles.txt` を参照してください。新しいC#にはUnityが生成するmetaファイルが付属します。

- `PrecisionViewport`：通常Wheelを既存のPanへ接続。Shift+WheelのSetZoom、カメラ倍率、カーソル中心処理は維持。
- `PreviewViewport`（新規）：完成見本の表示倍率・移動量・画像外へのパン制限を管理。
- `PrecisionAssist`：見本内のWheel／Shift+Wheel／中ドラッグ／Home入力、画像のクリップ描画、読みやすい不透明パネル。
- `ContactRangeGuide`（新規）：正式な接触輪郭の表示。旧デバッグ表示とは別。
- `EraserController`：紙上にポインターがあるかをガイドへ伝える。
- `PrototypeGame`：開始時スナップショット、やり直し要求・キャンセル・確定。
- `PlayerProgress`、`CrumbEconomy`、`CrumbPiece`、`CrumbBall`：復元用データを保持し、経済・成長・個体状態を整合させる。
- `PrototypeHUD`、`WorkFlowHUD`：やり直しボタン／確認、接触ガイド設定、依頼詳細の情報分離。
- `SkillHUD`：空の通知を描画しない。やり直し時の空帯を解消。
- `CrumbTradeHUD`：見本・確認表示中の背面ボタン操作を抑止。
- `RuntimeUXChecks`（新規）：WindowsプレイヤーでのUX回帰チェック・画面キャプチャ。
- `Editor/UXBuild`（新規）：通常Windowsビルドと既存Editorチェック実行。
- `Packages/manifest.json`、`packages-lock.json`：Unity標準JSONシリアライズモジュールを追加。作業開始時データのコピーに使用。

## ズームとスクロール

作業側は、通常Wheelの1段を基準画面（1280×800）の80px相当のパンとして既存の `Pan(from,to)` へ渡します。カメラの紙面レイ変換を再利用するため、World上の接触サイズ・擦る性能は変わりません。横方向は中ドラッグで移動します。

見本側はカメラを操作せず、同じ1～4倍・1段1.2倍の操作を画像表示矩形へ適用します。カーソル下の画像位置を基準に拡大し、表示枠でクリップ、パン量を画像端で制限します。見本の操作は作業用紙のカメラ位置・進捗に影響しません。閉じて開き直すと全体表示です。

## 接触ガイド

`Game.Contact` の `ContactFootprint.OutlinePoint` を直接使用して96点の輪郭を作ります。この構造体は実際の消去計算 `Weight` と共通です。別の円形カーソルや独立した判定サイズは作っていません。

半透明の細い緑色の線を紙面上に重ね、面は広い輪郭、辺は細長い向き付き輪郭、角は小さな輪郭として表示します。R回転、個体の角摩耗、スキルによるサイズも同じ接触データから反映します。線の太さはWorld値0.006で、塗りつぶしはありません。

デフォルトON。設定は同じ起動中・依頼間で維持します。紙上にポインターがある作業中だけ表示し、メニュー・見本・やり直し確認・結果では非表示。OFFは表示だけを止め、消去判定には触れません。既存F4デバッグは別に残し、通常はOFFです。

## テストの再実行

Unity Editorの `Keshiya.Editor.UXBuild.Run` は既存Editorチェックと通常ビルドを実行します。コードだけのビルドは `Keshiya.Editor.UXBuild.BuildOnly`。

Windows版に `--ux-test -screen-fullscreen 0 -screen-width 1600 -screen-height 900` を付けると追加チェックと画面保存を実行します。8依頼完了までのチェックは `--external-test`。通常試遊ではこれらのフラグを付けません。

依頼文照合のテスト用文字列についてのみCRLF/LF差を正規化しています。ゲーム内文章を変更したり、誤字を自動修正したりしていません。
